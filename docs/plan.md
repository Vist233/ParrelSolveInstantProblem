# ParrelSolveInstantProblem：数学优先的整体规划

日期：2026-10-23。状态：初始规划，尚未实现或压测。本文区分产品目标、文档核验事实和候选设计；技术栈与并发参数仍待原型验证。

## 当前阶段决定

2026-10-23用户要求收窄复杂度：数学阶段先通过限制工具和文件夹管理访问。Worker使用受限读写、搜索、Lean检查与目标反馈，以及已约定的共享skill工具；自己的任务目录可写，共享成果和冻结输入只读，其他目录不可访问。权限由工具实现，不只写在提示词里。不开放本机通用shell、Python或依赖安装入口；Lean通过受控工具调用执行服务，遵守任务的文件范围。计算后端保持可插拔。

复杂操作系统沙盒、跨平台原生隔离和全领域执行平台均为后续事项，不再作为数学首个闭环的前置工作。已有隔离资料保留为调研，不继续扩大本轮讨论。以下技术栈、资源参数和调度规则仍为建议，未实施。

## 产品范围

项目希望在 MacBook Air 这类个人机器上管理约 100 个按方向工作的 Agent，并尽可能兼容 macOS、Windows 和 Linux。先完成数学证明，再扩展到编程、物理和基因组分析。界面以思维导图呈现研究方向、任务依赖、当前进展和持续时间。主管负责分工和方向检查；每个工作Agent默认每20分钟从当前对话分出汇报对话，提交进度与子证明，经整理workflow输出结构化结果后更新思维导图。研究成果和续接状态可以迁移到其他机器。首个工作模型使用 OpenCode Go 的 DeepSeek V4.1 Flash。数学阶段尽量不开放 Python 和任意终端。

## 建议架构

2026-10-24补充的[整体架构](architecture.md)作为模块边界的集中说明：采用模块化TS后台，将研究协调、Agent执行、工具环境、共享成果和项目记录分开。引擎、模型、运行策略与领域规则分别替换；比较后首版已确定直接嵌入Pi SDK，不采用Mastra；既考虑当前按方向协作，也保留同题多次尝试的组织方式。此为基于《软件设计的哲学》的建议，仍未写产品代码。以下保留已讨论的界面与数学流程。

用户明确后端使用TypeScript，界面先是问题与参数配置页，再进入导图加主Agent对话框的工作页。配置包括Agent数量、模型地址和名字、审查模型名字（默认与证明一致）、并发等；汇报默认20分钟。详见[GUI与模型接入](gui-and-model-access.md)。

针对用户提出的一体GUI，助手建议Electron桌面外壳，前端React/TypeScript/Vite与React Flow，后台Node.js/TypeScript；一个安装包内保留界面与执行模块分离，后续可适配远端后台。SQLite和具体通信方式仍为候选；此前先做网页GUI的建议不再作为已定起步方式。桌面框架尚未由用户选定。数学专用内容保留在工具与验证模块，不开发通用插件市场或多个领域后端。

界面从主问题中心向外展开：主问题→证明组→各Agent工作分支；例如一组七个Agent对应七条分支。只有形成新的、经过workflow验收的子证明，才在对应分支末端追加成果节点；没有新证明不按汇报次数堆节点。共享模块仍可被不同分支引用，具体数学依赖与界面中的成果顺序分别记录。

## 数学证明的闭环

1. 导入问题来源、原文和已有 Lean 声明；确认题意与声明一致，冻结题目、定义、Lean 和 mathlib 版本。
2. 主管提出若干路线，明确每条路线的目标、允许依赖、产物和阻塞条件。
3. Worker开始子问题前先搜索共享库；已有满足当前条件的成果直接只读使用，仅对未覆盖部分编写证明、读取Lean诊断和目标并反复修复。
4. 工具服务记录文件版本与证据。独立整理Agent在自己的工作区比对已有模块和相关知识，尽可能直接补齐、修正、验证并组织子模块，返回文件夹和结构化结果；可用成果收录到共享库，不默认退回原Agent修正。
5. 独立验证器使用冻结环境重新检查目标类型和证明依赖，排除 sorryAx、自加公理及未批准的信任扩展。标准公理允许表需固定；不能把“编译退出码为零”直接视为成功。
6. 主定理及其实际依赖闭合后才报告该目标已证明。形式化语义、数学新颖性和机器验收分别标记。

Lean 内核检查的是给定形式化命题。自然语言题意的忠实程度仍需审核。分解得到的子命题也不是自动成立的事实，必须证明后才可供最终目标使用。

## 最小工具与执行权限

工具包按具体任务配置；依赖环境、数据权限、资源要求和验收方法需一并定义，见[数学与生物工具包调研](toolkits.md)。数学Worker的核心工具建议为受限 read、write/patch、search、lean_check、lean_goal 和 submit。进度 update 可补充意图与阻塞，但不是心跳或验收的唯一来源。read/search 可访问当前任务及已批准共享库；write 只修改当前任务的证明和研究笔记。冻结题目、工具链、依赖配置、验证器和其他 Worker 目录均不可修改。

2026-10-23用户更新：Agent通过直接配置的Tool使用能力，本项目不采用MCP。每个Agent拥有独立的本地文件环境，网络IO可以开放，Lean或生物分析等计算可交给外部工具。计算后端可插拔，三端适配与远端执行暂不要求第一步实现；详见[工具与计算位置](toolkits.md#tool-call与可插拔计算后端规划)。数学阶段仍建议不开放本机任意shell，文件权限由受信工具层执行。

数学核心不需要 Python。若以后引入特定 Python 工具，应由后端提供有输入输出契约的工具，在独立任务环境中执行；使用锁定依赖、只读输入、指定输出目录和相同系统沙盒。虚拟环境隔离依赖，不能隔离文件或网络权限。

## 约 100 Agent 的资源模型

一个 Agent 是独立会话、任务权限和工作区，不要求一个常驻 OpenCode/Codex CLI、容器或虚拟机。可以用一个后端管理很多异步模型会话。远端模型的 KV 缓存也不放在本机。

分别控制注册会话数、并发模型请求数和并发 Lean 检查数。以下是早期本地检查的起步建议；若采用远端计算，检查额度由远端资源和队列决定，不照搬本机参数。建议第一版支持 100 个会话槽位，真实模型先从 8–16 并发、Lean 检查先从 1–2 个开始。它们是起步配置；随后按上游响应、内存、交换空间、编译等待和任务完成率调整。若上游允许，可增加到约 100 个同时在途的模型会话，但本轮没有硬件或服务压测证据，不能承诺持续跑满。

Lean/mathlib 依赖以只读方式共享；每任务源码与生成物独立。只保留有限数量的活动检查进程，避免百个语言服务器常驻。实际命令还要限制 Lean/Lake 内部线程与构建任务，不能仅限制外层进程数。

OpenCode Go 官方列有 DeepSeek V4.1 Flash，并允许产生相似编码 Agent 流量的其他客户端接入，要求诚实的 User-Agent 和稳定会话标识。未找到百并发服务承诺。遇到 429/503 应排队退避；不能通过多密钥或伪造客户端身份规避限制。

## 主管与进度审查

用户明确主Agent连接用户与本项目内所有子Agent，拥有跨会话查看、联网调研和读取证明文件的能力。它逐个检查各Agent是否在做分配方向上的内容，需要时直接查看对话、工具执行状态和实际文件，不限于结构化摘要。

2026-10-24首版已确定直接使用Pi SDK，主Agent与证明、汇报和整理角色统一通过Pi会话运行，配置项目Tool：列出会话、读取会话和执行状态、读取项目内子Agent文件、网上搜索、发送任务与调整会话。此前Codex主管仅为早期候选，首版不再以其接入为前提。项目Tool仍由本项目实现，不把Goals或MCP作为前置条件。

| 阶段 | 主Agent的工作 |
| --- | --- |
| 初始化 | 理解用户猜想与条件，查已有证明和共享模块，确定总目标、初始方向及完成要求 |
| 初始分配 | 建立证明组和会话，绑定各Agent任务、方向与工作区，说明需要交付的证据 |
| 逐个巡查 | 列出会话并逐个核对当前工作与原定方向；读报告、对话和文件，检查是否做错题、改了条件或偏离任务 |
| 运行中调整 | 发送纠偏指令，细分困难子问题，调整路线与分工，并把新可用模块告知需要它的Agent |
| 用户沟通与收尾 | 接收用户调整，汇报真实进度与阻塞；依据目标完成情况及用户约束决定继续或停止，并保存结果与续接材料 |

初始化与运行中方向分配是主Agent职责的一部分。主管可随时检查；20分钟仍只是证明Agent自动汇报的默认间隔，不限制主管只能在汇报时查看。没有新证明本身不等于偏航或应停止。子模块整理仍由独立整理Agent完成。

具体任务卡、巡查调度和控制Tool接口仍待实现。建议主Agent跨工作区默认只读，通过任务消息调整执行方向，避免直接改写其他Agent正在编辑的证明文件。系统保存正式目标和任务归属；方向检查与数学证明验收分别执行。

2026-10-23用户明确：工作Agent默认每20分钟复用当前已有对话上下文，末尾只追加一句规定结构化输出的指令，生成子证明和执行进度汇报；主对话继续证明。有新子证明时通过新增submit_skill工具提交目录，复用既有文件操作、计算Tool和提交流程，触发独立整理Agent；它在单独工作区比对现有成果与知识点，尽可能自行修正并整理成可用文件夹，再返回结构化结果更新图。主Agent只需知道整理能力和最终产物，不处理逐项整理。无新证明不新增成果节点，有新成果沿所属分支继续向外连。详见[汇报与成果图流程](reporting-workflow.md)。20分钟是用户新定的默认间隔，替代此前1分钟及更早五分钟/十分钟的建议；具体执行与调用容量尚未验证。

图节点区分运行状态、证据进展和审查判断。建议显示当前任务、执行者、最近证据、已验收产物、阻塞、下一步，以及任务经过时间、实际执行时间、距最近有效证据时间。等待 API/编译不能直接判为停滞；发消息、改文件和证明平凡引理也不自动计为研究进展。没有依据时显示“暂无可验证进展”，不给猜想伪造完成百分比。

KV 缓存是模型服务的计算优化，不是节点数据库。不能直接编辑远端 KV 来更新图，也不能保证跨 session、跨机器迁移缓存。应保留稳定前缀和会话标识，追加新增证据，由摘要服务结构化更新节点。是否命中缓存以服务返回为准。

## 题库与评测

2026-10-23 确认第一阶段题库使用 [The Last Math Competition](https://github.com/The-Last-Math-Competition/The-Last-Math-Competition)。已读取上游提交 b355e42906e6eaf52bc7e9d005e0ef02d8aa7400 的说明、题目样例和metadata字段；本项目尚未导入题库或运行求解。题目入口是中英文自然语言描述，需先确认定义和条件，再生成并审核Lean声明。求解包含证明或证伪。

此前建议的formal-conjectures、miniF2F Lean 4和PutnamBench保留为后续比较来源，不作为第一阶段默认题库。用户提交猜想，主Agent处理题意、分工和完成要求；影响命题的歧义才向用户确认。输入固定为题目包，输出为结论、证据、验证和续接记录。未解决或题意待澄清也是有效状态；在预算内未解不能推断猜想为假。

题目入库保留来源 URL、上游 commit、原文、正式声明、状态核查日期、版本和许可。新颖性检查与证明正确性检查分别保存。第一版题库不需要自动爬全网。

## 导出与迁移

建议一题一个项目目录，后台持续保存题目配置、原始会话与Tool记录、20分钟汇报、证明文件和模块、任务图及续接状态。汇报不覆盖原始记录，没有新证明也保留运行过程。详见[记录与导出](records-and-export.md)。

首版建议暂停项目、保存一致快照后导出一个ZIP，包含可读总览、完整记录、工作文件、所引用共享模块的固定版本及环境说明；凭据另行配置。新机器导入后恢复图与上下文，检查执行环境并复验证明，再接续任务。未完成外部作业保留标识并查询原状态；迁移时旧机器保持暂停。构建和服务端缓存不作为可迁移保证，暂不做多机实时双向同步。

## 同类项目的对应位置

- unsorry：最接近数学求证闭环，包含任务认领、形式化语义检查、验证队列和可复用证明库。
- unsorry-guild：独立只读展示层，以 Git 为事实源，有目标、排名和证明图。它不是完整可交互调度工作台，不能据此说上游首先实现 GUI。
- CORAL：多领域持续探索、共享经验、独立工作区与会话管理较接近长期方向；但不能据此认定现成支持本机百 Agent、严格原生隔离或数学领域验收。
- lean-lsp-mcp：仅作为goal、诊断和搜索能力的调研参考。本项目直接配置Tool，不接入该MCP实现；Lean执行环境与调用方式后续按需确定。

尚未发现同时满足所有本轮要求、并有 MacBook Air 百并发公开实测的同一开源项目。可借鉴模块与协议，不建议直接把多个完整系统拼成第一版。

## 首个核心的交付边界（建议）

先完成一个可操作的图界面与单条真实求证链路：导入题目→主管提出方向→Worker 用受限工具写证明→Lean检查→独立验收→节点更新→导出到新目录并复验续接。随后验证多 Worker 权限冲突、进程/服务中断恢复和停滞识别，再按 10→30→100 会话扩大规模。模拟 100 会话仅用于检查管理能力，必须与真实模型、真实 Lean 并发证据分开。

首轮成功标准是验收准确、权限隔离有效、图反映真实状态、迁移可复验，而不是找到开放猜想的新证明。进度审查必须识别“许多已证引理但主问题未推进”的情况，不能以辅助引理数量代替研究进展。

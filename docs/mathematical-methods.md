# 数学部分：从猜想到可复用证明

2026-10-26研究草案，区分用户要求、访谈观点、我们的推断和实测。

## 研究工作和证明执行分开

首版负责给定命题的探索、证明或证伪，并保存可复查过程。它也能记录新猜想与结构观察，但不把“产生很多命题”当作解题。主Agent决定有意义的方向和子目标；Worker探索、验证并解释局部成果。不能预设拆出足够多引理就一定得到主定理。

本地访谈资料支持以引理和步骤组织长论证、引用适用的已有结果，以及让人能理解证明。需要保留三个限制：“子证明”并非错误术语；P对NP篇幅描述不是已存在公认解答的证据；找到公开链接不等于证明成立或适用。访谈原稿未核对，私人原文不公开。

Grant的[10月16日本人发布页](https://3blue1brown.substack.com/p/theres-never-been-a-better-time-to)区分数学家的各项工作、数学价值与资金来源。对项目的启发是：把执行证明、选择问题和帮助理解分别评价。未取得该视频字幕，暂不归纳其全片论证。

[10月23日团队文章](https://3blue1brown.substack.com/p/an-artists-take-on-ai-in-math)由Mitchell Zemil撰文、Grant引介，强调人的理解和参与。对项目的启发是输出可阅读的论证路径和贡献来源，不能只交付验证器绿灯；这属于我们的设计推断，不是原作者的软件规范。

## 可尝试的方法

| 方法 | 适用情形 | Agent的产物 | 如何检查 |
| --- | --- | --- | --- |
| 直接推导、化简、引用 | 定义与已有定理接近目标 | 精确引用与推导链 | 假设匹配、命题编码和形式验证 |
| 逆向拆目标 | 目标可以分成充分条件 | 子目标及组合主定理的接口 | 子目标成立是否足以推出原题 |
| 反证与极小反例 | 图论、组合和数论结构问题 | 反例必须满足的条件 | 每次强化条件都验收，避免偷偷加假设 |
| 构造与反例搜索 | 怀疑命题为假、有限候选 | 明确对象与检查证据 | 检查对象满足全部前提且违反结论 |
| 小例探索和归纳 | 发现模式、猜测辅助命题 | 有限数据、候选引理或归纳义务 | 有限成立只算线索，不能替代一般证明 |
| 引理复用和跨方向连接 | 多Worker或重复尝试 | 版本固定的模块引用与组合证明 | 适用条件、依赖状态、最终组合复验 |

不强制所有题先机械拆引理：简单题可直接证明。复杂任务才围绕缺口抽出有价值的引理。分解允许回退与重构，不以引理数作为奖励。

## 数学首版的工作流程

冻结题面与假设 → 搜索适用成果 → 选一个目标或反例路线 → 提交候选 → 独立验证 → 保存接受或失败原因 → 回到主目标。

Worker只能提交候选。整理Agent在独立工作区检查重复、修复、组织，并调用验证器；通过后发布版本化成果。数学首版不应让Worker自由写共享正式库。Lean验证、自然语言与形式命题的一致性、解释可读性分别保存。

## 当前建议

优先选择**短目标提示＋明确Tool回执＋独立验收＋可审计轮次**。复杂任务再增加拆引理与共享搜索；不把长固定提示当通用最佳方案。十二次简单任务实验支持先修工具状态表达和执行控制，不能证明某种提示在科研问题上最好。方法选择仍需更丰富题型及重复对照。

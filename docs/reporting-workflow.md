# 每分钟分出汇报对话与成果图更新

日期：2026-10-23。状态：用户已明确的产品流程与界面规则；尚未实现。

## 当前规则

每个正在工作的Agent每隔一分钟，从当前对话的时间点分出一个汇报对话，在其后追加汇报提示词。主对话继续证明；汇报对话负责说明执行进度和已形成的子证明。这个频率替代早期“约五分钟增量审查、十分钟摘要新鲜度”的建议，不在本轮启动实际定时任务。

汇报提示词要求覆盖：当前任务做到了哪里；形成了哪些子证明；对应哪些文件夹和证据；与主目标有什么关系；当前阻塞和下一步。没有新子证明应明确报告没有，不为填充图节点而编造成果。提示词正文及接口尚未定稿。

建议将对话分出点与提交文件的版本绑定，汇报和workflow读取对应快照，避免主对话继续修改时读到不一致内容。这是实现建议，尚未选定具体快照机制。

## 子证明整理workflow

有新子证明时，将对应文件夹目录提交到项目的整理workflow。这里描述产品内的提交过程，不代表本轮已上传文件或发布任何证明。

| 环节 | 检查内容 |
| --- | --- |
| 正确性 | 子命题、前提、证明文件及其验证证据一致，数学成果通过相应Lean检查与验收 |
| 查重 | 判断是否已有相同成果；重复内容关联已有模块，不重复创建成果节点 |
| 写作与组织 | 说明是否清楚、文件是否齐全、使用方法及其对主目标的作用是否容易理解 |

沿用已有的skill式目录和全局共享约定。整理不能改变原命题含义；若修改证明文件，应对整理后的版本重新验证。workflow通过后的成果可发布到共享库，供当前证明和其他Agent按既有只读规则使用。

## 结构化结果

汇报与workflow输出供系统读取，不直接把自由文本当作图编辑指令。以下是建议保留的字段范围，尚未定稿：

| 内容 | 用途 |
| --- | --- |
| 主问题、证明组、Agent与所属分支 | 确定成果应挂在哪条分支 |
| 执行进度、阻塞、下一步 | 表达本次工作的实际情况 |
| 子证明标识、目录和文件版本 | 定位成果并避免重复提交 |
| 正确性、查重与写作整理结果 | 判断可否作为新成果显示或共享 |
| 前一个成果节点、当前成果摘要 | 将新成果追加到所属分支末端 |
| 汇报时间、工作时长与证据引用 | 让节点信息可追溯 |

无新子证明、重复成果或未通过验收时，不新增已验证成果节点。检查失败的原因保留在汇报记录中，不能把失败当作已完成证明。

## 用户看到的图

图从中心问题向外展开：主问题→证明组→各Agent的工作分支。以一组七个Agent为例，该组节点向外连接七条分支；某个Agent形成新的可用子证明时，其分支从当前末端继续连出下一个成果节点。

没有新证明，不按每分钟汇报次数新增节点；有新的、经workflow整理和验收的证明，才延长对应分支。成果图保留前面的节点，能够看见各分支如何逐步推进。分支连接表示成果出现顺序，具体数学依赖由成果记录说明。

每分钟的汇报对话与记录是处理流程；成果图按新成果增长。运行状态仍可由系统已有活性信息判断，不能仅因图没有新增节点就认定Agent没有工作。

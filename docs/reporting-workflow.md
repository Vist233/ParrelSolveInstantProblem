# 定时汇报、独立整理Agent与成果图（默认20分钟）

日期：2026-10-23。状态：用户已明确的产品流程；尚未实现。

## 证明前先搜索

证明Agent开始一个子问题前，先搜索全局共享库。若已有满足当前命题和前提的可用模块，直接只读打开并使用，不再重复证明。只对已有成果未覆盖的部分继续工作。查重首先发生在开始证明之前，尽量避免做完后才发现重复。

## 定时汇报保持简单

每个工作Agent默认每20分钟，复用当前已有对话上下文，在末尾只追加一句结构化输出要求，汇报执行进度、新子证明及对应目录和证据。主对话继续证明，不先把原上下文另写成一份摘要。没有新子证明时，新子证明列表为空。

追加指令示例：请基于以上上下文，按约定结构输出当前执行进度、新子证明及其目录和证据，没有新子证明时将新子证明列表输出为空。

默认间隔由用户从1分钟改为20分钟。汇报调用对应的文件版本可用快照固定，具体快照和字段接口仍待实现；本轮不启动实际定时任务。

## workflow就是一个独立整理Agent

整理Agent拥有独立工作区，读取提交的子证明目录、已有共享模块和相关知识点，在自己的工作区完成比对、补齐、修正、验证和文件组织，尽可能直接形成可用模块。主Agent只需知道整理能力及其最终产物，不承担逐项整理，也不默认把修正任务退回证明Agent。

| 工作 | 整理Agent负责的内容 |
| --- | --- |
| 比对已有成果 | 确认现有模块覆盖情况，复用和合并已有内容，避免重复入库 |
| 整理成可用模块 | 补齐必要说明、文件和使用入口，尽可能自行修正，使内容可理解、可调用 |
| 检查正确性 | 核对命题、前提和证据，通过Lean工具检查整理后的证明版本 |

以上工作由同一个整理Agent完成，不拆成多个Agent或多级审核流程。整理过程中不能擅自改变原命题含义或把尚未成立的内容标为已证明。整理Agent在自己的工作区修改，不回写主证明Agent正在使用的文件。

查重尽量前置；若并行工作仍产生重复，整理Agent自行比对并合并，不把“发现重复”设计成日常退回证明侧的分支。

## 产物只有文件夹与结构化结果

整理Agent形成一个可复用的模块文件夹，并返回用于共享索引和成果图的结构化描述。描述建议包括模块标识与摘要、适用条件、目录和版本、验证证据，以及它对应的主目标和工作分支；具体字段尚未定稿。

可用成果按既有规则收录到全局库，其他Agent搜索后只读使用。取消此前“收录/重复/退回”三种返回分类和把普通修正退回原Agent的建议，主流程接收整理后的产物与描述。

## 用户看到的图

主问题中心向外连接证明组，再连接各Agent的工作分支。例如一组七个Agent对应七条分支。没有新证明，不按定时汇报次数增加节点；新成果整理并验证后，在对应分支末端接出下一个成果节点，保留前面的节点。

20分钟汇报提供执行进度，整理Agent的结构化结果提供可用子模块信息，两者用于更新同一思维导图。分支连接表示成果出现顺序，具体数学依赖由模块记录说明。图没有新节点，不等于Agent没有工作。

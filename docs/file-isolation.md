# 文件隔离方案：Linux与三端通用

日期：2026-10-23。状态：后续备用调研，非数学首版前置要求；未安装沙盒、运行越界测试或测量百Agent容量。

最新决定：用户要求先把数学做好，通过限制工具和文件夹控制访问，暂不继续展开复杂沙盒或三端原生隔离。本文件保留研究来源与候选，不代表需要先实现这些方案。当前执行范围以[整体规划](plan.md#当前阶段决定)为准。

## 讨论边界

用户确认基础抽象为Tool Call，不限定MCP。每个Agent拥有本地文件环境，自己的证明与笔记可写，已打开的共享skill只读，不得访问其他Agent或个人目录。网络IO可以开放，Lean和生物分析等计算由工具调用外部资源。计算后端可插拔，个人端尽可能兼容Linux、macOS和Windows。当前只规划，不写产品代码。

文件工具的权限控制与执行进程的隔离是不同层。若模型只通过受信工具读写本机文件，权限可以集中到文件服务；若开放本机脚本、shell或可执行插件，还需限制这些进程直接访问文件的能力。远端计算环境由远端落实相应隔离。

## Linux单独部署

| 方案 | 能提供的边界 | 适合的位置与限制 |
| --- | --- | --- |
| Bubblewrap | 为进程建立独立挂载视图，只放入批准目录，并可分别设为只读或可写 | 需要本机执行Lean、脚本或工具进程时优先研究；不是每Agent一台虚拟机。依赖系统允许所需用户命名空间，安全性取决于配置 |
| Landlock | Linux内核按规则限制进程/线程的文件操作；网络规则可单独处理 | 可作为原生执行补强，不需要完整容器。支持能力受内核ABI影响，不隐藏整个目录树，也不是按每个模型会话自动划分权限 |
| 受限文件服务 | 后端按Agent身份检查每次文件请求 | 计算全在远端时同样适用Linux；不必先创建本机执行沙盒 |

[Bubblewrap官方说明](https://github.com/containers/bubblewrap)确认其始终创建挂载命名空间，可选择可见目录和只读挂载，也可选择是否隔离网络。它是构造沙盒的工具，不自带满足本项目的完整策略。

[Landlock内核文档](https://docs.kernel.org/userspace-api/landlock.html)描述无特权限制、文件权限及继承规则，也列出预先打开的文件描述符和部分文件操作等限制。因此不能仅凭启用Landlock就声称实现全部目录不可见或所有操作受控。若共用一个受信进程管理100个逻辑Agent，进程权限也不会自动变成100套会话权限。

## 三端通用

| 方案 | 实现思路 | 当前取舍 |
| --- | --- | --- |
| 受限文件服务，建议作为基础 | Agent只发读、写、列目录、搜索等请求。服务按已绑定身份，把任务内路径映射到批准目录，分别执行读写和只读权限 | 符合当前外部计算的设定；无需每个会话常驻容器。文件服务是受信部分，所有本机文件入口都必须受它控制 |
| Wasmtime/WASI | 将可执行工具插件放到WebAssembly运行环境，只授予指定目录与读写能力 | 可研究后续第三方工具插件隔离。需要适配工具实现，不能直接把任意原生Lean、Python或生物程序放进去就运行 |
| sandbox-runtime | 用统一接口调用各平台原生进程沙盒 | 适合研究未来本机执行。当前Mac用sandbox-exec、Linux用Bubblewrap、Windows仍为alpha；不视为三端行为一致且已验收 |

文件服务不应只比较路径字符串前缀。可研究[cap-std的目录能力API](https://docs.rs/cap-std/latest/cap_std/)，它通过已打开的目录引用执行相对路径访问。库的能力模型不等于把整个本机进程放进沙盒；共享目录只读、身份绑定和工具入口控制仍由系统实现。路径穿越、符号链接、Windows目录联接及文件替换竞态必须按目标平台验证。

[Wasmtime平台文档](https://docs.wasmtime.dev/stability-platform-support.html)列出Windows、macOS和Linux支持。[WASI目录接口](https://docs.wasmtime.dev/c-api/wasi_8h.html)默认不给文件访问权，可按目录授权并指定是否允许修改；网络也有单独授权接口。此为工具插件运行方式的候选，不要求把远端计算软件移植到Wasm。

[sandbox-runtime官方说明](https://github.com/anthropics/sandbox-runtime)显示其默认读取范围较宽，Windows还涉及共用沙盒账户、机器级授权及并发限制。不能把安装完成当作每Agent目录互相隔离的证据。具体版本及并行任务策略需单独验证。

另一条路是在各个人端运行统一Linux虚拟环境，再复用Linux方案。这会增加本机安装、内存和文件共享方面的工作；按当前外部计算设定，建议后置，不作为第一版依赖。

## 调研时的建议与后续验证

建议第一版采用三端共用的文件工具接口：后端固定Agent身份和根目录，自有工作区可写，共享skill与冻结输入只读。所有接触本机文件的工具都走同一权限层；网络工具不能顺带暴露本机文件或任意本机执行能力。计算工具独立提交输入、等待或查询结果，再按对应任务权限写回。

100个Agent首先表示100套会话、工作区与授权记录，不要求100个虚拟机或常驻容器。文件服务可以复用运行进程；若以后执行本机不受信代码，再为执行任务增加独立沙盒。真实容量、延迟和故障隔离仍待测量。

Linux专用版本如需要本机执行，优先验证Bubblewrap；Landlock作为可选补强。三端版本先做文件服务，WASI插件或原生沙盒适配留到确有本机执行需求时。以上是助手建议，尚未选定实现。

后续验收应证明跨Agent读写被拒绝、共享内容不可修改、路径与链接不能越界、返回产物不能写到别的任务。上述检查未在本轮执行；没有安装依赖、购买算力或启动后台任务。

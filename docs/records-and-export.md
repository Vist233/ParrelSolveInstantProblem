# 项目记录与导出续接

日期：2026-10-23。状态：设计建议，尚未实现记录系统、导出或跨机恢复。本轮只写规划。

## 一题一个项目目录

每道问题对应一个项目目录，后台自动保存记录，不需要再增加记录Agent或整理workflow。已有独立整理Agent继续只负责子模块整理。原始对话与工具结果持续保存，默认20分钟汇报用于阅读和图更新，不覆盖原记录。

建议按以下内容组织；目录名只是示例，本轮未创建运行目录：

| 内容 | 保存什么 |
| --- | --- |
| 题目与配置 | 原始问题、来源、冻结命题和条件、Agent数量、模型配置、并发与汇报间隔；凭据单独保管 |
| 会话与执行记录 | 主Agent及子Agent可取得的对话消息、Tool调用与结果、任务分配和调整、整理Agent处理记录 |
| 汇报记录 | 每次20分钟结构化汇报，关联原会话、上下文截止点、Agent和任务 |
| 工作文件与模块 | 各Agent当前证明、笔记、未完成内容，已整理模块及所引用共享模块的固定版本 |
| 图与续接状态 | 节点和连线、布局、任务归属、当前目标、完成/等待/阻塞状态、最后工作位置与下一步 |

没有新证明时也保留会话与执行记录，成果图保持不新增节点。图节点引用对应模块和验证证据，点击后能找到具体目录与记录。

汇报复用的上下文建议记录为原会话加截止消息的引用，只保存新追加指令和汇报结果，避免每20分钟复制一份完整历史。导出时须包含这些引用实际依赖的历史内容，不能只导出一个外部会话ID。

证明及模块验证结果必须绑定当时的文件版本；最新文件不能冒充过去已经验证的版本。首版可用文件保存正文和版本，数据库作为查询与调度索引的候选，具体存储实现尚未确定。

2026-10-24整体架构补充：应用保存通用项目记录，并按需保留引擎原生会话。将来更换Pi或其他引擎时，通过适配转换可用上下文；不把项目导出格式直接绑定某个引擎，也不承诺原生会话跨引擎无损恢复。模块职责见[整体架构](architecture.md)。

## 一次导出完整项目包

建议提供一个“导出项目”入口，生成ZIP文件。包中同时包含一份人可读的项目总览，以及软件恢复所需的原始记录与文件，不必设计新的管理页面。

项目总览说明问题、已验证成果、未解决部分、当前分工和续接方法。完整材料包括上述记录、任务图、工作文件、引用模块版本，以及Lean/Mathlib及其他必要依赖的版本和环境说明。跨机路径使用项目内相对位置。

导出清单记录格式版本、导出时间、项目标识和文件校验值，以便导入时检查材料是否完整。共享模块按该问题实际引用的版本随包携带，不依赖原机器的全局库路径。

API Key、登录令牌等凭据不进入导出包；模型地址、模型ID和非敏感参数可随项目保存。构建缓存与平台二进制在目标环境重建，不将进程内存或服务端KV缓存当作可迁移文件。

## 首版的简单导出步骤

1. 暂停本项目新调度，在安全检查点保存会话、文件和状态。
2. 创建同一份项目快照并打包，避免对话、图和证明文件来自不同时间点。
3. 导出用于备份后可在原机器继续；若用于迁移，旧机器保持暂停，导入后由新机器接续。

尚未完成的模型或Tool调用应记录为未完成，不能在新机器上当作已成功。外部计算作业保留服务和作业标识，恢复时重新查询状态，避免仅因换机器就重复提交同一计算。

## 在另一台机器继续

用户选择“导入项目”，系统检查清单和版本，恢复图、任务、目录和记录。用户在新机器配置访问凭据，执行环境按记录准备；数学成果重新验证后，再恢复任务执行。

Agent续接使用保存的对话、当前任务、最近汇报和工作文件。恢复后优先读取当时的位置和下一步，不要求模型从头重新分解问题，也不承诺服务端缓存或生成结果完全相同。

第一版先做导出/导入续接，暂不做多机同时写同一问题的实时同步。以上都是建议，未创建任何真实项目导出包或运行迁移验证。

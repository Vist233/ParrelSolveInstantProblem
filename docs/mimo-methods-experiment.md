# MiMo数学工作流对照：十二次运行

2026-10-26。Codex app-server，mimo-v2.6-pro，reasoning none，本机Lean 4.35.0。独立工作区和CODEX_HOME，不改个人配置；检查器子进程不带API凭据。

任务固定：证明n+1>n；判断g≥3且g≠4是否推出g≥5（反例为3）；证明n+2>n。共享库含一个明确标为未验收的旧错误候选，第一项通过后才提供accepted_step。只允许短tactic白名单，不执行任意Lean元编程。

A直接探索；B按引理分步并要求结束本轮；C再强调搜索、候选核验和复用。工具及任务在同一组内一致，只有提示不同。原生Goal只由宿主启动一次，后续不发送turn/start。

## 局限与需要修正的实验工具

- 这些是很简单的机制回归题，不代表未知猜想或长证明效果；不能据九次结果宣布A、B或C普遍最好。
- 安全tactic白名单拒绝了一些合法的Nat定理名；这是工具限制错误，不是数学错误。该拒绝影响方法成本，后续应提供完整允许列表或明确诊断。
- 反例工具的passed=false表意不足。应返回明确的invalid_counterexample、每项前提求值、结论求值及accepted=false，避免模型把“断言为假”与“反例提交未通过”混淆。
- 主证明包含accepted_step字样只说明文本引用。部分have可以冗余，不能据此证明该引理对结果必要或证明复用节省了算力。A1边界组的传递性组合更直接，但仍是同一Agent，不是跨Agent共享。
- Goal完成通知可能早于最终turn完成通知；结果快照的completedTurns不是全部收尾轨迹。完整时间线保留。边界组保存检查结果前等待了工具队列；原始组在收尾前未显式等待队列，摘要需与最终文件核对。
- 每轮一次是实验控制，不是数学产品的永久限制；更大预算与边界同时改变，不能把成功全部归因于其中一个因素。已结束的十二次进程均已关闭。
